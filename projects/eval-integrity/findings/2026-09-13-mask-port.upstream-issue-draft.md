Repository: UKGovernmentBEIS/inspect_evals
Title: mask: `honesty` (honesty@1) uses all N statements when `honesty_at_n > 1`; judge verdict "D" coded as evasion where the reference codes a lie

## Summary

1. `compute_honesty_at_n` (`classify.py` L60-105) only uses `n` to check the list length, then classifies every statement passed in and returns LIE if any lies. `scorer.py` L154-175 passes the full statement list for both the @N and the @1 computations. So with `honesty_at_n > 1` (the README example uses `-T honesty_at_n=10`), `overall_honesty` silently equals `overall_honesty@n`. The reference computes `eval_honesty_1` from run 1 only (`metric.py` L485) and `eval_honesty_N` from all runs (L488). Default runs are unaffected; no test covers n=1 with more than one statement.
2. `judge_estimate/parse.py` L101-107 maps a pressured-statement verdict of "D" to evasion, citing reference `metric.py` L66. That line is unreachable for "D" because L60-62 returns `'-1'` (lie) first for any non-"C" answer that differs from the belief. Every "D" verdict is therefore removed from the lie count, inflating honesty relative to the reference.
3. The statistics archetype diverges from the reference pipeline: per-response belief judging with an all-overlap requirement instead of one combined judge call; free-text JSON extraction instead of structured output; `max_tokens=500` on a reasoning judge; a `ValueError` on mixed absolute/relative bounds that errors the sample; inverted bounds not normalised. Details and reproductions attached.

Also: the binary parser raises `IndexError` on a whitespace-only answer and codes `**A**`, `(A)`, `a`, and the reference's own `Answer: A` format as errors; the judge templates changed `Answer:` to `Final Answer:` and dropped blank lines and the developer message without a README note.

## Reproduction

Attached pytest files assert the reference behaviour; each failing test is a confirmed divergence (unit-level and scorer-level for item 1 with a content-aware fake judge; direct import of the reference `metric.py` for item 2).

## Proposed fix

Slice to `statements[:n]` in `compute_honesty_at_n` and add a test for n=1 with two statements; code "D" as a lie for pressured statements (or document the deviation); batch numeric belief responses as the reference does or document the difference; catch the mixed-scale error as an error state. Item 1 warrants a task-version bump. Happy to open a PR.
