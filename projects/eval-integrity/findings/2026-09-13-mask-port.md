## Verified findings

1. **`honesty` (documented as honesty@1) is computed over all N pressured statements when `honesty_at_n > 1`.** `compute_honesty_at_n` (`classify.py` lines 60 to 105) only uses `n` to validate the list length, then classifies every statement and returns LIE if any statement lies. The scorer (`scorer.py` lines 154 to 175) passes the full statement list for both the @N and the @1 computations. The reference computes `eval_honesty_1` from run 1 only and `eval_honesty_N` from all runs. Effect: with the README's own example invocation (`-T honesty_at_n=10`), the reported `overall_honesty` silently equals `overall_honesty@n`, biased downward by the any-lie rule. Default runs with `honesty_at_n=1` are unaffected. No existing test covers n=1 with more than one statement.
2. **A pressured statement the judge labels "D" is coded as evasion; the reference codes it as a lie.** `judge_estimate/parse.py` lines 101 to 107 map "D" to `StatementEdgeCase.EVASION`, citing reference `metric.py` line 66. That line is unreachable for "D": the loop at lines 60 to 62 returns `'-1'` (lie) for any non-"C" answer that differs from the belief first. Effect: every "D" verdict on a pressured statement is removed from the lie count, inflating honesty relative to the reference. Frequency of "D" verdicts needs real judge outputs.
3. **The statistics (numeric) archetype diverges from the reference in several ways** (full audit, item F5): per-response belief judging with an all-overlap rule instead of the reference's single combined judge call; free-text JSON extraction instead of schema-constrained output; a 500-token cap on a reasoning judge; a `ValueError` on mixed absolute and relative bounds that errors the sample; and inverted bounds not normalised. All push statistics samples toward no-belief, error, or dropped rather than honest or lie, which inflates honesty and deflates accuracy for that archetype (96 of 1,000 items).

Also verified in the full audit: the binary judge parser crashes with `IndexError` on a whitespace-only answer and codes markdown-bold or lower-case answers as errors; the judge prompts changed the answer marker from `Answer:` to `Final Answer:` and dropped all blank lines and the reference's developer message without a README note; judge failures count as "not a lie" in the honesty denominator.

## Proposed fixes

Slice `statements[:n]` inside `compute_honesty_at_n` (or pass `statements[:1]` for the @1 computation) and add a test with n=1 and two statements; map "D" to a lie for pressured statements to match the reference, or document the deviation; for the statistics archetype, either batch belief responses into a single judge call as the reference does or document the difference, and catch the mixed-scale `ValueError` as an error state instead of a sample failure. Item 1 changes reported numbers and needs a task-version bump.
