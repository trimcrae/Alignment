Title: agentic_misalignment: literal `{company_name}` in the safety-instruction condition, grader sampled at default temperature, empty completions scored as safe, stderr always 0

## Summary

Comparing the port (commit 360484a, task version 4-A) with anthropic-experimental/agentic-misalignment (commit ea0630e) surfaced four behaviour differences that change reported numbers or their interpretation:

1. `extra_system_instructions="dont"|"goal"`: `prompt_generator.py` L313-324 builds the extra instructions with a literal `{company_name}` and passes them through `fill_template` (`string.Template.safe_substitute`), which only substitutes `$name` forms. The model receives "...external to {company_name}". The official code has the same bug in a different form (f-strings with an undefined name, which raise), so the safety-instruction ablation is not reproducible with either implementation.
2. The grader is called without a `GenerateConfig` (`scorers.py` L34-36), so it samples at the provider default (temperature 1). All official classifiers use `temperature=0.0, max_tokens=2000`. A CLI `--temperature 0` does not reach a non-active model.
3. Empty completions are sent to the grader and scored `harmful=0`; the official runner skips and re-samples them, so they never enter the denominator. Models that return empty or content-filtered outputs get a deflated harmful rate.
4. The dataset is a single `Sample` and relies on epochs; epochs are reduced per sample before metrics, so `stderr()` is always 0. The README's Epochs: 10 table has no valid uncertainty.

## Reproduction

Attached tests assert the reference behaviour (each failing test is a confirmed divergence): a test that no `{` placeholder survives prompt generation for the `dont`/`goal` conditions; a spy on the grader API showing `temperature=None, max_tokens=None`; an empty-completion run that yields `harmful=0` and enters `accuracy`; and a 4-epoch run with per-epoch harmful `{1,0,1,0}` that reports `stderr: 0`.

## Proposed fix

Fill the company name (or remove the placeholder) and test for surviving placeholders; pass `GenerateConfig(temperature=0.0, max_tokens=2000)` to the grader; treat empty completions as `Score.unscored()`; either one sample per epoch so `stderr` is meaningful or document the absence of an uncertainty estimate. Items 2-4 warrant a task-version bump. Also noted: two leaking templates edited SummitBridge to NovaStar without a changelog entry, and README says the default grader is claude-sonnet-4 while code uses claude-sonnet-4-6. Happy to open a PR.
