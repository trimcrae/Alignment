## Verified findings

1. **MakeMeSay's judge verdict parser takes the first `0` or `1` character anywhere in the reply, and codes a missing digit as "not aware".** `makemesay/game.py` does `re.search(r"[01]", text)`; the reference raises a `ValueError` unless the reply is exactly `"0"` or `"1"`. So a judge that explains before answering, for instance by writing "Sentence 1 ... Sentence 2 ... 0", is recorded as aware although it said not aware, and a judge that answers "Yes" or returns nothing is recorded as not aware. Both directions change the headline: the first turns wins into "user aware of manipulation", the second turns correct guesses into wins. This confirms upstream issue #2395 and shows it is not a one-way error.
2. **All four MakeMeSay rates collapse when run with more than one epoch.** The outcome lives only in the score's `answer` field, and Inspect's default reducer keeps `answer` only when every epoch agrees, otherwise setting it to none. Every sample with a mixed outcome then stays in the denominator of all four rates and enters the numerator of none, so all four are biased downward and their sum reads out the mixed fraction. A two-sample example gives rates summing to 0.5 instead of 1.0. This matters because repeating a stochastic multi-turn game across epochs is the natural way to run it, and the published result the README cites used 32 runs per word.
3. **MakeMeSay's judge prompt is formatted twice, so braces in the model's guess crash the sample or inject the codeword.** The prompt is built with an f-string and then passed through `str.format` again. A guess containing JSON, a set, or a placeholder raises a `KeyError` after the full conversation has been paid for; a guess containing `{}` silently substitutes the real codeword into the text shown to the judge, biasing it toward "aware".
4. **Make Me Pay's mark defaults to an undocumented third-party model**, not the evaluated model and not the reference's mark, so a run that sets only the model under test measures it against a different lab's small model. The port also gives the mark one fewer decision point than the turn cap implies and wastes a generation after every donation, and it never implemented the reference's language-model donation detector, so pledges phrased in prose are missed. Its reported metrics are the mean and variance of the donation amount; the reference's primary metric, the donation success rate, is not produced at all.
5. **InstrumentalEval and CoCoNot silently discard the grader temperature they document.** InstrumentalEval passes `temperature=0.0` to a default grader whose family has reasoning enabled, and Inspect drops sampling parameters for those models with only a warning, so the judge runs at temperature 1. CoCoNot sets temperature 0 at the task level, which by design reaches only the active model, so its grader also runs at provider defaults and without the reference's system message. In both cases the documented setting is not in effect and per-sample verdicts are not reproducible. CoCoNot's own README notes an unexplained sensitivity to the choice of grader, which this would contribute to.
6. **Aggregation and fidelity gaps.** CoCoNot micro-averages compliance per category while the paper states its contrast scores are averaged across sub-categories, whose sizes differ by more than threefold; its evaluated model is capped at half the reference's token budget while the README states there are no known deviations. InstrumentalEval codes grader replies that bracket or bold the decision, the exact form its own template shows, as invalid rather than following the reference's fallback, and it samples the evaluated model at provider defaults where the reference pinned temperature 0, which is the most likely explanation for the gaps the README tabulates against the original implementation.

One MakeMeSay item is latent rather than active and is recorded as such: the debrief prompt is attributed to the manipulatee, so its own words can satisfy the "said the codeword" check, but no codeword in the default or harder word lists is in the trigger set, and on the easy list the bug is masked. It would become an active, deterministic inflation for any custom word list containing an ordinary noun, which is what the debrief text itself invites.

## Proposed fixes

Anchor the judge parser to a bare digit and fail loudly or mark the sample unscored otherwise; carry the outcome in the score value rather than only in `answer`, or set an explicit reducer, so epochs aggregate correctly; stop re-formatting the already-interpolated judge prompt; document the Make Me Pay mark default and align its turn accounting, or state the deviation; pass an explicit grader config in both InstrumentalEval and CoCoNot and pick a grader that honours temperature; and align CoCoNot's aggregation and token budget with the paper or document both.
